# Как запускать и собирать проект

## Локальный запуск

1. Открой **Run → Edit Configurations...** в IntelliJ
2. Выбери **DashboardApplication**
3. Найди поле **Active profiles** и напиши туда: `local`
4. Нажми **OK**
5. Запускай как обычно (зелёная кнопка ▶)

После запуска приложение доступно по адресу:
**http://localhost:8081/spec/login**

---

## Сборка jar для продакшна

Выполни в терминале (в папке проекта):

```
mvn clean package -DskipTests
```

Готовый jar будет в папке `target/`. Его нужно залить на сервер.

---

## Важно — не делай этого!

Не добавляй в файл `application.properties` строчку:

```
server.servlet.context-path=/spec
```

Если она там появится — на продакшне будет ошибка 404.

Для локальной разработки эта настройка уже прописана в отдельном файле
`application-local.properties` — он подхватывается автоматически когда
указан профиль `local` (шаг 3 выше).

## Техническая документация (для разработчиков и ИИ-ассистентов)

### Архитектура роутинга на проде

На продакшн-сервере стоит nginx, который слушает порт 8080 и распределяет трафик:
- запросы с префиксом `/spec` → проксирует на `localhost:8081` (наше приложение)
- остальные запросы → другое приложение на сервере

nginx **стрипает** префикс `/spec` перед передачей в приложение:
```
браузер:     GET /spec/dashboard
nginx:       стрипает /spec → GET /dashboard → localhost:8081
приложение:  обрабатывает /dashboard
```

Именно поэтому `server.servlet.context-path=/spec` в jar **ломает прод** — приложение начинает ждать `/spec/dashboard`, а получает `/dashboard` → 404.

### Как приложение знает о префиксе /spec

Префикс задаётся через свойство `app.base-path=/spec` в `application.properties`.

`GlobalModelAttributes.java` читает это свойство и добавляет переменную `basePath` во все Thymeleaf-шаблоны автоматически через `@ControllerAdvice`.

В шаблонах все ссылки строятся через неё:
```html
<a th:href="${basePath + '/dashboard'}">...</a>
```

В JavaScript — через переменную `BASE_PATH`:
```javascript
const BASE_PATH = /*[[${basePath}]]*/ '';
fetch(BASE_PATH + '/api/uploads')
```

### SecurityConfig — критичные правила

Файл: `src/main/java/com/emias/dashboard/config/SecurityConfig.java`

Все редиректы Spring Security **обязаны** использовать `basePath`, иначе после логина/выхода браузер попадёт на другое приложение по адресу `/admin`, `/login` и т.д.:

```java
.defaultSuccessUrl(basePath + "/admin", true)   // после успешного логина
.failureUrl(basePath + "/login?error")           // после неверного пароля
.logoutSuccessUrl(basePath + "/")               // после выхода
.accessDeniedHandler((req, res, e) -> res.sendRedirect(basePath + "/"))
.authenticationEntryPoint((req, res, e) -> res.sendRedirect(basePath + "/login"))
```

Эти строки неоднократно ломались при доработках — следи за ними.

### Профили Spring Boot

| Файл | Когда загружается | Что содержит |
|------|-------------------|--------------|
| `application.properties` | всегда | базовые настройки, без context-path |
| `application-local.properties` | только при профиле `local` | `server.servlet.context-path=/spec` для локального запуска |

На проде профиль не задан → `application-local.properties` игнорируется.
